# 一句话知识动画视频生成系统：实习完整实施计划

> 状态：规划稿，尚未实现或验证。创建日期：2026-11-16。以实习任务书、报告模板和用户提供的参考视频为依据；技术选择为建议，需通过真实测试确认。

**目标：**独立完成一个低成本、无旁白的知识动画视频生成系统：用户输入一句话，大模型生成知识脚本与分镜，小模型适配分镜并参与动画选择，程序合成文字、动态图表和音乐，导出可展示的 MP4，完成数据集测试、源码说明、报告与录屏。

**架构：**网页输入与编辑 → 百炼 qwen4-max 生成结构化脚本 → 本地小模型预测分镜类型 → 直接生成视频，生成后可修改分镜与重新生成 → 本地动画模板与音乐合成 → MP4、分镜和测试记录。先完成固定模板最小版，再验证大小模型联动。

**技术候选：**Python、Streamlit、中文文本分类模型、HTML/CSS/JS 动效或 Python 图形渲染、FFmpeg、pytest；以环境检查为准，不预先承诺某库已安装。大模型使用百炼 qwen4-max，具体额度以控制台为准；本地 Ollama 可作备选，小模型原型使用本地 Qwen3.5 0.8B，中文 RoBERTa 保留为备选。具体版本以账号额度、模型访问和电脑测试确定。

## 3. 系统范围与验收

输入：一句中文主题、可选 16:9/9:16、主题色与时长。默认 16:9、无旁白。输出：带背景音乐的 MP4、可编辑分镜 JSON、生成/测试记录。参考片是风格目标，不作为现有自动生成能力的证据。

最小成品支持 4 类场景：标题/概念、左右对比、矩阵表格、结论；数据变化图作为第二阶段。每幕必须可读且时间足够，数学与数字必须来自用户或经核验数据，不允许模板凭空编造。缺少矩阵数值时退回文字模板或提示补充。支持编辑镜头文字和手选模板。一次生成可预览与导出，失败时显示具体阶段和可重试信息。

验收样例：囚徒困境生成完整可播放视频，再用另一个不同知识主题生成并检查，验证内容不是只替换标题。视频通过 ffprobe 和 ffmpeg 解码检查，人工完整观看并试听音乐、字幕、节奏、画面。输出分辨率、时长、模型效果以实测为准。

## 5. 分阶段执行清单

### 阶段 0：明确任务与准备环境

- [ ] 对照任务书和报告模板列出提交清单，询问第 2 节不明确事项并记录老师答复；不将未回复视为同意。
- [ ] 检查 Python、Git、FFmpeg、浏览器、磁盘、CPU/内存/GPU；记录版本、失败信息及安装来源。
- [ ] 建立私有 GitHub 仓库、README、忽略规则和计划文档；核验仓库可见性。后续每个可运行阶段做一次清晰提交并推送；不隐含自动同步。
- [ ] 百炼核对免费额度和到期时间，开启用完即停，再以极短请求验证响应和用量；有意外计费风险时停止。
- [ ] 音乐先由用户提供或选择有权使用的本地文件；明确不上传仓库。

**完成标准：**环境检查记录、仓库可见性、免费额度开关和老师疑问状态明确；不声称模型已接入。

### 阶段 1：确定内容结构，先生成一条固定样片

- [ ] 围绕囚徒困境写 4–6 幕脚本；每幕记录标题、屏幕短句、画面描述、时长、动画类型和必要数据。
- [ ] 核对收益矩阵、计算和结论适用条件；记录可查来源，不能把模型生成当作事实证明。
- [ ] 实现项目 JSON 校验：镜头列表非空、时长为正、类型有效、必填文字不为空；提示错误位置。
- [ ] 先用人工脚本渲染标题、对比、矩阵、结论模板；缺失矩阵数据时降级或报错，不生成假数字。
- [ ] 按时间线合成音乐；处理静音、音乐太短、超长字幕和无可用字体等情况。无音乐时允许无声视频导出并明确提示。
- [ ] 使用 ffprobe 检查轨道、时长和尺寸，ffmpeg 全片解码；人工完整观看和试听，检查字是否看清、音乐与动画是否抢拍。

**完成标准：**一条使用手写脚本的无旁白 MP4 可播放；明确这还不是自动生成系统。

### 阶段 2：大模型接入与交互

- [ ] 定义结构化脚本字段：`title`、`scenes[]`；每幕含 `text`、`visual_description`、`duration_seconds`、`data`（可为空）。大模型不负责最终模板分类。
- [ ] 封装一次模型调用，限定输出长度及格式；解析失败、接口超时、无额度时明确提示，不将密钥写日志。
- [ ] 网页实现一句话输入、风格和时长选择、生成脚本、逐幕修改、重新生成；显示当前状态与费用前提。
- [ ] 对一批主题测试 JSON 可解析性、指定格式遵从、内容基本正确性，记录提示词、模型版本、日期、失败案例与人工核验依据。

**完成标准：**用户输入两种不同主题可得到不同的、可编辑且通过校验的脚本；API 实际额度及成本有记录。

### 阶段 3：小模型数据与适配

- [ ] 查找和下载与文本/镜头分类有合理关系的公开数据，核对许可、语言、类别与格式；记录链接和局限，不能把不相关数据硬说成分镜数据。
- [ ] 制定四类标签规则和边界，准备真实任务风格的中文分镜样本；公开数据与自己标注的数据分别记录。可以使用模型辅助草拟，但需本人核对标签并如实记录。
- [ ] 先去重再按类别分层划分训练/验证/测试，固定随机种子，记录数量及比例；相同或近似样本不得泄漏到测试集。
- [ ] 加载中文预训练分类模型，训练或按老师要求适配；记录训练设置、时间、硬件、日志和模型版本。没有执行微调时不能写已微调。
- [ ] 在未参与训练的测试集计算准确率和各类别精确率/召回率/F1，保留混淆和错误案例；另用实际生成的分镜做独立场景测试。
- [ ] 输出类别和置信度；低置信度提供默认概念模板及人工修正，不能把分数当成真实性或事实准确度。

**完成标准：**小模型能被系统调用并真实影响模板选择；数据来源、训练与测试可复现，指标为实际结果。

### 阶段 4：整合、对照与视频质量

- [ ] 完成流程：用户输入 → 大模型脚本 → 数据校验 → 小模型分类 → 用户可修改 → 模板渲染 → 音乐合成 → 导出。
- [ ] 对同一批分镜比较大模型建议模板、小模型模板及人工修正，记录模板匹配率、失败情况和所需人工修改；不预设谁更好。
- [ ] 测试空输入、非法 JSON、API 失败、模型加载失败、模板缺字段、超长文字、音乐缺失、输出文件冲突；确保错误可理解并保留已有作品。
- [ ] 对不同知识主题各生成样片；人工核对事实、文字停留时间、屏幕边界、转场、节拍、音乐响度和导出质量。记录每次修改。
- [ ] 限制结论：样本少、人工评分主观、模板数量有限；小模型识别分类不证明知识正确或视频更美观。

**完成标准：**至少两个不同主题完成端到端测试，其中一条作为作品，测试结果和缺陷清单真实可查。
